## 1. Executive Summary & Core System Architecture

Falz is a multi-tenant SaaS application engineered specifically for Saudi real estate brokerages. It unifies property listing management, private owner CRM, bidding logs (Som), GIS parcel mapping, visitor client portals, and administrative operations into an integrated, localized Arabic interface.

### Architectural Principles
1. **Multi-Tenancy:** Every data entity is strictly scoped by `officeId` (Tenant Isolation).
2. **REGA Compliance:** Strict capture and validation of FAL License numbers, Owner National ID/IQAMA numbers, and Dates of Birth.
3. **Arabic-First Design:** RTL native layout, localized terminology, custom Arabic currency notation (`ريال سعودي` / `SAR`).
4. **Data Isolation (Public vs. Internal):** Private bidding details, internal staff notes, and owner identity remain completely hidden from non-authenticated public users.

### Module 1: Navigation & Deal Type Separation (`#page-properties`)

#### 1.1 Functional Description
The Properties view provides access to all office listings with absolute isolation between Sale and Rent listings.

#### 1.2 Specifications
- **Sidebar Action:** Clicking **"العقارات" (Properties)** opens the master properties page.
- **Top Tab Bar:** Includes two prominent tabs:
  1. **`للبيع` (For Sale)** — Active by default. Queries listings where `dealType == SALE`.
  2. **`للإيجار` (For Rent)** — Queries listings where `dealType == RENT`.
- **Isolation Rule:** Mixed listings (Sale + Rent) must NEVER appear in the same table or grid view.
- **Filter Bar:** Must provide multi-criteria real-time filtering within the active tab:
  - Listing Status (Published, Draft, Archived)
  - Main Category & Dynamic Sub-Types
  - Price Range & Area Range
  - Payment Method (Cash / Bank)
- **Real-Time Tag/Filter Sync:** Any new property tag, custom category, or sector added via admin controls must instantly sync with the global filter options without page reload.

#### 1.3 Acceptance Criteria
```gherkin

  Given the user clicks "العقارات" in the main sidebar

Scenario: Switching to For Rent listings
  Given the user is on the properties page
  When the user clicks the "للإيجار" (For Rent) tab
  Then the table refreshes to show ONLY listings with dealType == RENT

Scenario: Real-time filter sync
  Given an admin creates a new custom property category "شاليه"
  When an agent opens the property filter bar
  Then "شاليه" appears as a selectable option without needing to refresh the page.
```

### Module 3: Pricing Engine, Bidding System ("Had" vs "Som") & Auto-Hide

#### 3.1 Functional Description
Supports fixed asking price ("حد"), public bidding ("سوم"), private bid logs, auto-expiry of bid visibility, and date display toggles.

#### 3.2 Specifications
- **Pricing Mode Toggle:**
  - `LIMIT` (حد / Fixed Price): Exposes asking price input.
  - `BID` (سوم / Highest Bid): Exposes highest bid input & bid logging table.
- **Private Bid Log (Som Log):**
  - Logs `amount`, `bidderName`, `bidderPhone`, `bidDate`.
  - Public view: Shows highest bid amount only. Bidder name and phone remain staff-only.
  - Editable `bidDate` to support manually backdated bids.
- **Bid Auto-Hide Timer (`bidAutoHideDuration`):**
  - Dropdown options: `شهر` (1 Mo), `شهرين` (2 Mos), `3 أشهر`, `6 أشهر`, `سنة`, `بدون إخفاء` (Never).
  - Timer affects **public view only**.
  - When elapsed, public view displays `"يوجد سوم"` (Bid exists) but masks the monetary amount.
- **Bid Date Visibility Toggle (`showBidDate`):**
  - Toggle switch on listing form (Default: OFF).
  - OFF: Public view hides the bid date.
  - ON: Public view displays the bid date.
  - Staff view: Always displays bid date.

#### 3.3 Acceptance Criteria
```gherkin
Scenario: Public viewing of an auto-hidden bid
  Given a property has a highest bid of 500,000 SAR logged 3 months ago
  And bidAutoHideDuration is set to "ONE_MONTH"
  When a public visitor views the property details
  Then the price displays "يوجد سوم" (Bid Exists)
  And the numeric amount 500,000 is hidden from the public.

Scenario: Staff viewing an auto-hidden bid
  Given the same property above
  When an authenticated employee views the property in dashboard
  Then the full bid amount 500,000 SAR and bidder phone/name are fully visible.

Scenario: Logging a backdated bid
  Given an agent has a property set to BID pricing
  When the agent adds a new bid and manually sets the bid date to a past date
  Then the bid is saved with the manually entered date, not the current timestamp.
```

### Module 4: Payment Logic (Cash vs. Bank Filtering)

#### 4.1 Specifications
- **Listing Classification:**
  - `CASH`: Accepts cash payment only.
  - `BANK_AND_CASH`: Accepts bank financing and cash (`يقبل البنك والكاش`).
- **Filter Behavior (Public & Internal Search):**
  - Filter for **"كاش" (Cash):** Returns ALL properties (`CASH` + `BANK_AND_CASH`).
  - Filter for **"يقبل البنك" (Bank Approved):** Returns ONLY properties set to `BANK_AND_CASH`.

### Module 6: Specifications, Master Bedroom & Conditional Fields

#### 6.1 Specifications
- **Master Bedroom Field (`masterBedrooms`):** Dedicated counter for en-suite master bedrooms.
- **Bathroom Rule:** Total `bathrooms` cannot be less than `masterBedrooms`.
  - Enforced constraint: `bathrooms >= masterBedrooms`.
  - Auto-suggest: When increasing total bedrooms, suggested bathrooms default to `bedrooms + 1`, respecting the master bedroom lower bound.
- **Apartment Entry Type (`entryType`):**
  - Shown only for `APARTMENT` property type.
  - Options: `مدخل خاص` (Private Entry) | `مدخل مشترك` (Shared Entry).
  - Rendered as badge on property cards and available as filter option.
- **Conditional Field Visibility:** Automatically hide irrelevant fields when certain property types are selected:
  - Selecting **"أرض" (Land):** Hides Bedrooms, Bathrooms, Master Bedrooms, Building Area, Floor Number, Entry Type.
  - Selecting **"شقة" (Apartment):** Shows Entry Type. Hides irrelevant land-only fields.
  - Selecting **"فيلا" (Villa) / "دوبلكس" (Duplex):** Shows all bedroom/bathroom fields. Hides Entry Type.
- **Plot Dimensions (N/S/E/W):**
  - Accepts Western dot (`12.5`), Western comma (`12,5`), and Arabic decimal (`١٢٫٥`).
  - Auto-normalize to `Float` on save.
  - Fields are optional.
- **Zero/Empty Value Hiding:** If numeric fields (e.g., age, bedrooms) are `0` or null, they are hidden entirely from public cards/details (never show "0 غرف نوم").
- **Optional Specification Fields:**
  - Street Width (`عرض الشارع`) — in meters.
  - Property Age (`عمر العقار`) — New / Years.
  - Floor Number (`رقم الطابق`) — for apartments.
  - Building Surface Area (`مسطح البناء`) — in m².

#### 6.2 Acceptance Criteria
```gherkin
Scenario: Bathrooms cannot be less than master bedrooms
  Given an agent sets masterBedrooms to 3
  When the agent tries to set total bathrooms to 2
  Then validation prevents it with message "دورات المياه لا يمكن أن تقل عن عدد غرف النوم الرئيسية"
  And bathrooms remains at 3 (minimum).

Scenario: Land type hides bedroom fields
  Given an agent selects property type "أرض" (Land)
  Then the Bedrooms, Bathrooms, Master Bedrooms, Building Area, and Floor Number fields are hidden.

Scenario: Zero values hidden on public view
  Given a property has bathrooms set to 0
  When a public visitor views the property details
  Then "دورات المياه" row is not displayed at all.

Scenario: Entry type shown only for apartments
  Given an agent selects property type "شقة" (Apartment)
  Then the "نوع المدخل" dropdown appears with options "مدخل خاص" and "مدخل مشترك"
  When the agent changes type to "فيلا"
  Then the "نوع المدخل" dropdown is hidden.
```

### Module 9: Operations (Reserved Status & Contract Expiry Auto-Archive)

#### 9.1 Specifications
- **Reserved Status (`RESERVED` / `محجوز`):**
  - Soft lock on listing. Shows `"محجوز"` badge on public card.
  - Public visitors cannot submit bids or requests.
  - Internal staff can edit details or transition status.
  - Manual status transition only (no automatic timer).
  - Records `reservedAt` timestamp when status changes to RESERVED.
- **Auto-Archive on Contract Expiry:**
  - Toggle `autoArchiveOnExpiry` (Default: ON) on the property form.
  - When `contractExpiryDate < currentDate`:
    - If ON: Property status transitions to `ARCHIVED`; in-app notification sent to agent.
    - If OFF: Warning in-app notification sent to agent; property remains active.
- **Deed Number:** Optional field. No validation error if empty (Notes override original PRD).

#### 9.2 Acceptance Criteria
```gherkin
Scenario: Reserved property blocks public requests
  Given a property has availability set to RESERVED
  When a public visitor tries to submit a viewing request
  Then the request button is disabled
  And a message displays "هذا العقار محجوز حالياً"

Scenario: Auto-archive on contract expiry
  Given a property has autoArchiveOnExpiry = true
  And contractExpiryDate was yesterday
  When the system runs the expiry check
  Then property status changes to ARCHIVED
  And an in-app notification is sent to the assigned agent.
```

### Module 10: Dashboard KPIs & Financial Analytics (`#page-dashboard`)

### Module 13: UI Polish, Zero-Value Hiding, Tag Sync & Arabic Dictionary

#### 13.1 Toggle Switch UI
- **Styling:** Adopts office `primaryColor` from `ThemeSettings`. Min touch target size **44px**.
- **High Contrast:** Clear visual distinction between ON and OFF states.
- **State Label:** Displays dynamic text label (`مفعّل` / `معطّل`) next to every switch.
- **Animation:** Smooth 200ms CSS transition on state change.

#### 13.2 Zero/Empty Value Hiding
- All public-facing cards and detail pages must hide rows where the value is `0`, `null`, or empty string.
- Example: Property with `bathrooms = 0` must NOT show "٠ دورات مياه" — hide the row entirely.

#### 13.3 Real-Time Tag & Filter Sync
- Any new property tag, custom category, or sector added via admin controls must instantly appear in the global filter options.
- Implementation: Invalidate and refetch filter options via React Query when mutations occur.

### Module 14: Dynamic Category/Classification Management

#### 14.1 Specifications
- **Custom Subtypes per Office:** Using existing `PropertySubtype` model.
- **"+ إضافة تصنيف عقاري مخصص" Button:** Available in the property form's subtype selector.
- **Contextual to Category:** Custom subtypes are filtered by the selected primary category:
  - Residential (سكني): e.g., Villa, Duplex, Apartment, Townhouse + custom additions.
  - Commercial (تجاري): e.g., Office, Shop, Warehouse + custom additions.
  - Agricultural (زراعي): e.g., Farm, Rest House, Raw Land + custom additions.
- **Role Access:** OWNER & MANAGER can add custom subtypes. AGENT can only select.

#### 14.2 Acceptance Criteria
```gherkin
Scenario: Adding a custom category
  Given a Manager selects category "سكني" (Residential)
  When they click "+ إضافة تصنيف عقاري مخصص" and type "بنتهاوس"

  And it appears in the subtype dropdown immediately.

Scenario: Custom categories are office-scoped
  Given Office A has a custom subtype "بنتهاوس"
```

## 5. Non-Functional Requirements

### 5.1 Performance
- Page load: < 3 seconds on 3G connection.
- Image lazy loading on property galleries.
- React Query caching for filter options and location dropdowns.

### 5.2 Security
- All protected API routes validate JWT session via NextAuth.
- Office-scoped queries enforce `officeId` check on every database call.
- Visitor endpoints sanitize response to exclude `internalNotes`, `bidderPhone`, `bidderName`, `ownerNationalId`.
- Input sanitization on all user-facing forms (XSS prevention).

### 5.3 REGA Compliance
- Owner National ID and Date of Birth enforced as required at form validation (Zod schema).
- Office FAL License Number pulled from global `Office.falLicenseNo` setting.
- Audit trail: All status changes logged via `AuditLog` model.
