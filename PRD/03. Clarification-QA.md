## 🔴 1. Critical Business Decisions

### Q1: Sale vs. Rent Separation & Navigation
- **Requirement Source:** `02. Notes.md` ("يختار المالك بيع أو ايجار ولا تظهر العقارات البيع والإيجار مع بعض إطلاقًا")
- **Decision:** **Option A — Tab-based separation on the same page**
- **Details:**
  - Sidebar keeps a single main action button **"العقارات" (Properties)**.
  - Clicking "العقارات" opens a page with two top tabs: **`للبيع` (For Sale)** and **`للإيجار` (For Rent)**.
  - Default active tab is **`للبيع`**.
  - Listings for Sale and Rent are completely isolated; switching tabs changes the active query so mixed listings are never displayed together.

### Q2: Client Accounts & End-User Portal
- **Requirement Source:** `02. Notes.md` ("هل للعميل حساب؟ العميل المستفيد من العقار ليس صاحب المكتب")
- **Decision:** **Option A — Lightweight Client Accounts using existing `Visitor` model**
- **Details:**
  - End clients (buyers/renters) can register and log in via phone number.
  - Clients can browse public listings, save favorites, submit viewing requests/inquiries, and track their request status.
  - Clients have zero access to internal office details (e.g., bidder phone numbers, owner identity, internal notes, signboards).

### Q3: "محجوز" (Reserved) Status Rules
- **Requirement Source:** `02. Notes.md` ("إضافة محجوز")
- **Decision:** **Option A — Soft lock, no new bids/requests, "محجوز" public badge**
- **Details:**
  - Adding `RESERVED` status to property availability.
  - Public view displays a **"محجوز"** badge.
  - Public users cannot place bids or submit interest/viewing requests on reserved listings.
  - Internal staff can edit details or transition status back to `AVAILABLE` or forward to `SOLD`/`RENTED`.
  - Manual status transition only (no automatic timer expiry).

### Q4: Auto-Archive on Marketing Contract Expiry
- **Requirement Source:** `02. Notes.md` ("خيار إضافية يختار هل يتم أرشفة العقار بعد انتهاء عقد التسويق تلقائيًا أو لا")
- **Decision:** **Option A — Per-property toggle (default: ON) + Notifications**
- **Details:**
  - Property form includes toggle: `أرشفة تلقائية عند انتهاء العقد` (default: ON).
  - When contract expiry date passes:
    - If ON: Property status automatically changes to `ARCHIVED`, and an in-app notification is sent to the assigned agent.
    - If OFF: Property remains active, but an in-app warning notification is sent to the agent ("عقد التسويق منتهي للعقار X").

## 🟡 2. Important Feature Decisions

### Q5: Som (Bid) Auto-Hide Timer
- **Requirement Source:** `02. Notes.md` ("إخفاء تلقائي للسومة بعد : شهر، شهرين، سنة، إلخ...")
- **Decision:** **Option A — Per-listing dropdown setting (Public hide only)**
- **Details:**
  - Property form field: `إخفاء السومة تلقائيًا بعد` dropdown (`شهر`, `شهرين`, `3 أشهر`, `6 أشهر`, `سنة`, `بدون إخفاء`).
  - Timer affects **public frontend only**.
  - After timer expires, public view displays "يوجد سوم" (Bid exists) but hides the monetary value.
  - Internal office staff and admins always see all raw bid amounts and complete history.

### Q6: Som (Bid) Date Visibility Toggle
- **Requirement Source:** `02. Notes.md` ("إضافة خيار لإظهار تاريخ السومة" vs. "ولا يظهر تاريخ السومة أبدًا")
- **Decision:** **Option A — Per-listing toggle, default OFF (date hidden)**
- **Details:**
  - Property form toggle: `إظهار تاريخ السومة للعميل` (default: OFF).
  - When OFF: Public view displays only the bid amount (if not auto-hidden), omitting the date.
  - When ON: Public view displays both bid amount and bid date.
  - Internal staff always see bid timestamps regardless of toggle.

### Q7: Master Bedroom & Auto-Bathroom Logic
- **Requirement Source:** `02. Notes.md` ("إضافة خيار غرفة نوم رئيسية ومع كل إضافة غرفة يزيد دورات المياه تلقائي")
- **Decision:** **Option A (Modified) — Master Bedroom count + Auto-suggest with Enforced Minimum**
- **Details:**
  - Added dedicated field `masterBedrooms` (غرف نوم رئيسية).
  - **Bathroom constraint rule:** Minimum bathrooms = Master Bedrooms.
  - User can add total bathrooms beyond Master Bedrooms count, but validation prevents setting total bathrooms lower than `masterBedrooms`.
  - Auto-suggest: When increasing total bedrooms, suggested bathrooms default to `bedrooms + 1`, respecting the master bedroom lower bound.

### Q8: Apartment Entry Type
- **Requirement Source:** `02. Notes.md` ("إضافة خيار للشقق مدخل خاص أو مدخل مشترك")
- **Decision:** **Option A — Dedicated dropdown + Public card badge + Filterable**
- **Details:**
  - Shown conditionally on Property Form when property type is `APARTMENT`.
  - Dropdown options: `مدخل خاص` (Private Entry) | `مدخل مشترك` (Shared Entry).
  - Rendered as a prominent badge on public property cards.
  - Added as a filter criteria in the public search bar for apartments.

### Q9: Dimensions Comma Support & Formats
- **Requirement Source:** `02. Notes.md` ("يقبل الفاصلة", "تعبئتها اختيارية")
- **Decision:** **Option A — Accept all comma/dot formats, normalize on save, fields optional**
- **Details:**
  - Plot boundary inputs (North, South, East, West lengths) accept Western dots (`12.5`), Western commas (`12,5`), and Arabic decimal signs (`١٢٫٥`).
  - Inputs normalize to standard `Float` values prior to saving in PostgreSQL.
  - Filling dimension fields remains strictly optional.

### Q10: Image Upload Limits & Compression
- **Requirement Source:** `02. Notes.md` ("مساحة الصورة الواحدة تكون مناسبة لتصوير الجوال الاحترافي", "الحد للصور 100 صورة")
- **Decision:** **Option A — 5MB max upload, 1920px sharp auto-compress, 100 photos limit**
- **Details:**
  - Max upload size: 5MB per file (supports high-res mobile photos).
  - Max photo count: 100 photos per listing.
  - Auto-compression pipeline using `sharp`: resizes to 1920px max dimension, converts to optimized JPEG/WebP.
  - Dual storage in S3: High-res original saved for PDF brochures; compressed version saved for web display.

### Q11: Video Display & Integration
- **Requirement Source:** `02. Notes.md` ("الفيديو يجب أن يعرض داخل الموقع")
- **Decision:** **Option B — External URL Embed Only (YouTube/Vimeo)**
- **Details:**
  - Property form accepts external video URLs (YouTube / Vimeo).
  - Embedded player renders directly inside the property detail page (`PropertyDetailClient.tsx`).
  - No direct video file upload to S3; direct video storage disabled to keep infrastructure lean.

### Q12: Toggle Switch UI Styling
- **Requirement Source:** `02. Notes.md` ("السويتش لونه غير مناسب ولا يظهر بشكل جيد")
- **Decision:** **Option A (Enhanced) — Office Primary Color + High Contrast & State Labels**
- **Details:**
  - Switch ON state adopts active office `primaryColor` from `ThemeSettings`.
  - Size scaled up to min 44px for easy mobile touch target.
  - Explicit high contrast against background.
  - Accompanying dynamic text label (`مفعّل` / `معطّل` or `نعم` / `لا`) next to every switch element for state clarity.

### Q15: City & District Management Architecture
- **Requirement Source:** `02. Notes.md` ("المدينة قائمة منسدلة يمكن للمستخدم إضافة خيارات إضافية")
- **Decision:** **Option A — Pre-seeded Saudi Cities (Locked) + Custom District Additions**
- **Details:**
  - Saudi Cities list pre-populated (Riyadh, Buraidah, Jeddah, Dammam, etc.) and locked against user editing.
  - Districts list pre-populated per city.
  - Office `OWNER` and `MANAGER` roles can add custom districts under any city.
  - `AGENT` role can select existing/added districts but cannot create new ones.
  - Sector Direction (`شمال`, `جنوب`, `شرق`, `غرب`, `وسط`) auto-assigned based on district, manually editable.
