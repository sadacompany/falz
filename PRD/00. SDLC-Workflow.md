### Phase 2: ❓ Clarification & Q/A
**Input:** PRD + Notes analysis  
**Output:** `03. Clarification-QA.md`  
**Status:** ✅ Complete (2026-08-05) — All 20 questions answered and logged

**Process:**
1. Cross-reference `01. PRD.md` with `02. Notes.md` to find contradictions & gaps
2. Identify ambiguous requirements, edge cases, and missing technical specs
3. Document all questions organized by module
4. Present to product owner for answers
5. Record all answers with timestamps

**Key areas requiring clarification (identified so far):**

#### 🔴 Critical (Blocks development)
- [ ] **Sale vs. Rent Separation:** Notes say "بيع أو ايجار ولا تظهر العقارات البيع والإيجار مع بعض إطلاقًا" — Does this mean completely separate listing views? Separate databases? How does the sidebar navigation change?
- [ ] **Client Accounts:** Notes ask "هل للعميل حساب؟ العميل المستفيد من العقار ليس صاحب المكتب" — Does the end client (buyer/renter) get a user account? What permissions? What can they see vs. office staff?
- [ ] **"محجوز" (Reserved) Status:** Notes say "إضافة محجوز" — What are the exact business rules? Can a reserved property still receive bids? Who can reserve? Auto-expire?
- [ ] **Auto-Archive on Contract Expiry:** Notes mention option to auto-archive property when marketing contract expires — What is the default behavior? Is it per-property or a global office setting?

#### 🟡 Important (Affects UX/Logic)
- [ ] **Som (Bid) Auto-Hide Timer:** Notes say "إخفاء تلقائي للسومة بعد: شهر، شهرين، سنة" — Is this hiding the bid from the public frontend only? Does it affect internal records? Is the timer per-bid or per-listing?
- [ ] **Som Date Visibility Toggle:** Notes mention "إضافة خيار لإظهار تاريخ السومة" — Is this a per-listing toggle or a global office setting?
- [ ] **Master Bedroom & Auto-Bathroom Logic:** Notes say "إضافة خيار غرفة نوم رئيسية ومع كل إضافة غرفة يزيد دورات المياه تلقائي" — What is the exact ratio? 1 bedroom = 1 bathroom? Does master bedroom count differently?
- [ ] **Apartment Entry Type:** "مدخل خاص أو مدخل مشترك" — Is this just a tag/badge or does it affect filtering on the public site?
- [ ] **Comma Support in Dimensions:** "يقبل الفاصلة" — Is this Arabic comma (٬) or Western comma (,)? How does this interact with number parsing?
- [ ] **Image Upload Specs:** "مساحة الصورة الواحدة تكون مناسبة لتصوير الجوال الاحترافي" — What resolution? Max file size per image? Compression policy? The limit is 100 photos per listing.
- [ ] **Video Embedding:** "الفيديو يجب أن يعرض داخل الموقع" — Max video file size? Supported formats? Is S3 the storage target? What about YouTube URLs mentioned in PRD?
- [ ] **Switch UI Issue:** "السويتش لونه غير مناسب ولا يظهر بشكل جيد" — What color/style does the product owner prefer? Dark theme compatibility?

#### 🟢 Nice-to-Have Clarifications
- [ ] **Deed Number Optional:** Notes confirm "رقم صك الملكية اختياري" — Does this override the PRD which lists it as a standard field?
- [ ] **Items "تحتاج مراجعة":** Two items in notes flagged for review — What specifically needs review? Are these features to keep or remove?
- [ ] **City/District Dropdown Extensibility:** "المدينة قائمة منسدلة يمكن للمستخدم إضافة خيارات إضافية" — Who can add cities? Only admins or any employee? Is there an approval workflow?

**Development Standards:**
1. **Branch per feature:** `feature/F1-sale-rent-separation`, `feature/F2-owner-crm`, etc.
2. **Commit convention:** `feat(module): description` / `fix(module): description` / `refactor(module): description`
3. **PR documentation:** Each PR must include:
   - Feature description & link to PRD section
   - Screenshots/recordings of UI changes
   - Database migration notes (if any)
   - Testing checklist
4. **Code quality:**
   - TypeScript strict mode
   - Zod validation on all inputs
   - Arabic RTL testing on every UI component
   - Prisma type-safe queries (no raw SQL unless justified)
5. **Coordination:**
   - Subagents assigned per feature module
   - Daily integration check to avoid conflicts
   - Shared component library updates coordinated

### 🟡 Schema Observations & Recommendations

1. **`PropertyOwner.nationalId` is nullable** — PRD says it's **mandatory** for REGA compliance. Need a migration to make it required, or enforce at app layer.
2. **`PropertyOwner.dob` is nullable** — Same as above, PRD says mandatory for REGA.
3. **`Property.streetWidth` is `String?`** — Should probably be `Float?` to support numeric filtering and comma parsing.
4. **`PropertyBid` has no `isHidden` / `status` field** — Needed for the auto-hide feature.
5. **`Property.soldAt` exists** but there's no `reservedAt` or `reservedBy` for the new Reserved status.
6. **Visitor model** — This seems to be the "client account" the notes ask about ("هل للعميل حساب؟"). It already has `passwordHash`, favorites, and property requests. Need to clarify with product owner if this is sufficient.
7. **No dedicated City/District models** — Current schema uses raw strings. PRD wants admin-managed dropdowns. Recommended new models:
   ```
   City (id, officeId, name, nameAr, createdAt)
   District (id, cityId, name, nameAr, direction, createdAt)
   ```
8. **Plan.maxMediaPerListing = 5** — Notes say limit should be **100 photos**. Needs plan-level update or override.
